# MAL_Class: evidence and remaining work

This is an independent multimodal research project. Legacy reports and scores are reference material, not experimental evidence for this project.

The three-branch architecture is explicit: Signature, Static PE and Dynamic/Behavior (ordered events plus execution graph) have separate encoders. Signature and Static PE now cross-attend directly at token level, then exchange evidence with dynamic event and graph tokens in both directions. This enables PE-only inference to relate structural clues before pooling, and hybrid inference to connect those clues with runtime activity. The direct Signature↔Static modules were added after the recorded three-branch experiments below; those historical metrics do not evaluate this latest architecture until retraining completes.

## MalBehavD-V1 dynamic-only sequence experiment

The CSV was verified locally against its pinned SHA-256. It contains 2,570 rows but only 2,543 unique executable hashes. Repeated hashes include 16 exact duplicate rows and 11 alternate trace variants. A leakage audit found 1,601 exact API sequences, 179 repeated-sequence groups covering 1,132 rows, 1,439 API-call multisets, 176 repeated-multiset groups covering 1,289 rows, and one connected component where an identical trace appeared under both numeric labels. Exact duplicate rows are removed; hashes sharing a trace or API-call multiset are grouped into one partition so neither sequence nor bag baseline can see an exact representation in both train and test. The contradictory component (12 hashes) is quarantined. Remaining alternate traces are kept together and probabilities averaged by hash before metrics. Hash-level source-label counts are 1,276/1,267 before quarantine. The resulting no-overlap split has 1,771 train, 380 validation, and 380 test hashes; the training vocabulary is fitted on training sequences only, and SHA-256 fingerprints for each split are persisted in the checkpoint.

Seeds 41/42/43, fixed leakage-controlled split seed 42, 64-dimensional, two-layer, four-head attention with learned label query and gated mean-API skip, early-selected by validation loss. Across the same 380-hash test split, attention balanced accuracy is 0.9412±0.0184 and AUROC 0.9872±0.0036 (sample mean±SD); the order-free mean-embedding baseline is 0.9613±0.0169 and 0.9939±0.0035. Shuffling API order yields attention balanced accuracy 0.9421±0.0120 on average, with mixed per-seed effects. The attention model wins thresholded balanced accuracy for one of three seeds, but loses on mean balanced accuracy and AUROC; this does **not** show an attention advantage or reliable order contribution. It suggests this API-only dataset is dominated by call identity and is a weak execution-flow benchmark. These seeds share one test set, so they measure initialization/training variance, not independent split variance. Top attention calls are inspection aids, not causal explanations.

The upstream authors document equal benign/malicious populations but do not specify whether numeric 0 or 1 means benign. All metrics therefore refer to raw source labels and must not be interpreted as malware recall/precision. The CSV has no family, API argument/status, graph, or ATT&CK/MBC labels; it cannot train the project's behavior or family heads. No binary was executed.

## Acceptance gates

The full-hybrid empirical gates remain unproven: family macro-F1 >= .88; ATT&CK mAP >= .82; hybrid improvement >= .02; Wilson 95% upper bound FPR <= .01; chain completeness >= .90; attention/IG agreement >= .75; shuffle macro-F1 relative decrease >= .15. Earlier EMBER candidates met the FPR bound only with extremely low malware recall. The 34k candidate's internal-holdout point FPR is 0.0091, but its Wilson upper bound is 0.0137, so it fails the stated confidence-bound gate. None of these static-only results establishes acceptable full-hybrid detection.

Even zero false positives among all 268 benign reports gives Wilson two-sided 95% upper bound about 1.41%, above 1%. At least 381 independent benign observations with zero false positives are needed for this particular bound. A validation subset needs its own denominator. Dataset access and labels, including benign versus undetected, must be verified from original sources.

The 1,000-row EMBER run is an execution smoke test only: it demonstrates the locked-source loader, temporal partition, model training, checkpoint, and inference path, but its held-out metrics fail the project gates and must not be presented as a research result. No manual annotations or accepted accuracy are inferred from unit tests. Dataset roles in the objective are preserved: WinMET/CAPE for hybrid experiments, MALVADA for report processing, EMBER for static pretraining, MalBehavD for dynamic pretraining, Oliveira/Catak for sequence baselines, BODMAS for temporal drift and capa for auxiliary evidence comparison. Each requires source/schema/license verification before import; static capa findings alone do not establish observed dynamic execution chains.

## Family-head diagnosis and repair

A diagnostic of the support-50 checkpoint on the first 64 unique TRAIN archive rows selects `berbew` as top-1 for all 64. Logits vary between samples, so the input path is not simply constant, but family ranking is collapsed on this cohort. The legacy head uses one shared scalar projection across family attention contexts; with only one modality its modality contexts are identical across queries. An optional `--family-head-variant labelwise` uses separate per-family projections/biases over the existing label-query attention contexts. Legacy checkpoints retain their original layout and outputs, and the default remains `legacy_shared` pending stronger evidence. This is a capacity hypothesis, not a verified solution to ranking collapse.

CPU best-checkpoint snapshots now clone tensor storage so subsequent optimizer steps cannot overwrite the selected epoch. A regression test covers this storage-aliasing bug; prior MPS snapshots copied to CPU and were not affected by this particular bug.

Frozen-context diagnostic: 512 TRAIN-prefix rows, first 384 fit the head, final 128 diagnose it, seed 42, 200 AdamW steps at 0.01, unweighted masked BCE. Shared-head refit: mAP 0.1624, all 128 top-1 predictions `berbew`. Labelwise refit: mAP 0.2188, top-1 counts `wacatac` 70, `berbew` 36, `flystudio` 21, `sfone` 1 (seven supported diagnostic labels). These are head-capacity diagnostics on a previously trained encoder, not held-out generalization scores. They justify a matched end-to-end experiment, not model promotion.

Matched end-to-end diagnostic: first 2,048 TRAIN-archive reports, seed 42, temporal 65/10/10/15 split (1,331/205/204/308), five supported training families, five epochs, batch 64, d_model 32, MPS, family_min_support 10. Shared-head selected validation mAP 0.1238 versus labelwise 0.1009; internal-test mAP 0.0875 versus 0.1127 (four supported labels), and calibrated macro-F1 0.0689 versus 0.0139. Both predict `berbew` for all 205 validation rows. The labelwise variant therefore has mixed results and does NOT resolve collapse end to end. Neither checkpoint is promoted. Next investigate loss imbalance, label supervision and model selection on training-only validation; do not infer a research improvement from this small cohort.

Label audit of that same cohort: only 124/1,331 training rows contain a retained family (354 have any family); `berbew` has 42 of those positives. Validation contains only 27 retained-family positives, including 14 `berbew`. Thus top-1 around 52% can arise from a majority-family predictor without discrimination. Future comparisons need a train-frequency-prior sanity baseline and fixed label space, not just top-k accuracy. This audit does not justify discarding benign samples or treating unknown families as benign.

### WinMET modality-dropout candidate (2026-10-26)

An audit found that the initial dropout implementation masked only the three pooled modality vectors; label-aware attention could still read the raw static/event/graph tokens. The earlier dropout-0.4 result is therefore a legacy summary-only regularization diagnostic, not evidence about true modality dropout. The implementation now samples masks before cross-attention and applies them to raw tokens, cross-modal keys and label-evidence memory. A regression test forces event/graph dropout and verifies logits do not change when those dropped inputs are altered. Reports record a `modality_dropout_scope`; the aggregation script rejects mixed scopes.

On seed 43, fixed sample/split, the corrected all-token dropout at 0.15 scored mAP 0.3125, calibrated macro-F1 0.1673, top-1 0.4462 and top-3 0.6154; no dropout scored 0.3407 / 0.2328 / 0.4923 / 0.6462. The matched bag baseline scored 0.1846 / 0.0927 / 0.4769 / 0.6000. No dropout is better on all four metrics in this one seed, but this single clustered validation split cannot select a deployment checkpoint or justify a default change. These new results are kept separate from the three-seed legacy summary-only dropout aggregate (attention mAP 0.297±0.027 / F1 0.187±0.025; bag 0.239±0.059 / 0.105±0.022). The 156-report withheld partition and official test sets remain unevaluated; labels are weak AVClass supervision. All checkpoints/reports are local ignored artifacts.

The selected seed-43 no-dropout checkpoint also passed validation-only flow ablation: shuffling events reduced mAP/F1 by 0.0606/0.0907; reversing flow reduced them by 0.0994/0.0947. Static-only lowered mAP by 0.1803, while dynamic-only lowered it by just 0.0039, indicating that execution-flow features can carry most family-ranking signal on this cohort. Removing graph edges changed mAP by only −0.0054 and slightly increased calibrated F1; breaking targets also had negligible effects. Thus attention is demonstrably sensitive to event order here, but useful entity-graph reliance remains unproven. This is a single-seed weak-label diagnostic, not causal proof.

### WinMET explicit three-branch attention experiment (2026-10-26)

The current architecture encodes Signature, Static PE and Dynamic/Behavior independently. Signature and Static PE tokens then cross-attend to the ordered event tokens and execution-graph nodes; event/graph tokens attend back to the structural evidence. Family/behavior learned queries consume the three branch summaries and the individual evidence memory. Inference traces expose top cross-branch pairs with event success, resource, target and graph-node context. A missing modality is masked from both attention values and updates; the static-only regression test confirms cross-attention cannot inject a synthetic dynamic signal.

## Trace-normalization corrections

Previously, unrelated files normalized to the same path category could share a graph node; the temporal resource relation was also unavailable for placeholder-style targets. Parsing now allocates anonymous report-local entity IDs while graph vocabulary uses only semantic resource tokens. Named objects are distinct; repeat access retains equality. Common process handles are bound only after a successful `OpenProcess`/`NtOpenProcess`-style acquisition, resolved within the owning process, and invalidated after a successful close; reuse and conflicting explicit PIDs have counterexample tests. Numeric handles are never treated as PIDs. CAPE `NtOpenKeyEx`/`RegOpenKeyEx` paths and key handles are resolved within a process; relative subkeys are joined to recognized predefined hives, and successful registry closes invalidate mappings. A less-specific hive-only `FullName` defers to a bound concrete handle, while different autorun keys remain conflicts. Unknown owners, failed opens, unknown handles, and unresolved file/key/socket handles remain unknown and cannot create a shared graph resource. In the 32-report diagnostic prefix, 2,349 registry acquisitions, 1,130 handle-based operations and 2,020 closes resolved; 1,192 target conflicts remain unknown. Duplicate/inherited handles and thread-handle-to-process resolution are not implemented. Process IDs and event indices are no longer graph features under `semantic_v2`. Old checkpoints missing the new tensorizer field explicitly retain legacy graph-token lookup; previously prepared traces must be rebuilt to recover lost identities.

Return values now distinguish successful NTSTATUS-style calls, Win32 registry `LSTATUS`, zero/invalid process handles, and missing or unrecognized status. The CAPE `status` boolean, when present, remains authoritative. This is based on documented API return conventions and still needs validation against actual WinMET report variants. A separate calibrated benign threshold is required to emit `BENIGN`; existing checkpoints without one return `UNKNOWN` for a non-alert, preventing low malware probability from being presented as proof of benignness.

The `T1547.001` evidence guard currently marks only standard `Run` and `RunOnce` registry paths (including the `WOW6432Node` form) and requires a successful ordered open/create plus value-write chain to the same key. Ordinary registry modifications can still support the separate `T1112` rule. Startup folders, other autorun locations, and broader ATT&CK detection guidance are not covered by this narrow rule; see [MITRE ATT&CK T1547.001](https://attack.mitre.org/techniques/T1547/001/).

The real WinMET reports have no top-level `static.pe` object; file metadata and string/YARA fields live under `target.file`. Static extraction now reads bounded file size/type, TLSH/ssdeep presence, strings and YARA categories from that schema. Missing imports, sections, entropy, overlay, export count or signer fields stay unknown instead of being fabricated as absent/zero. The 1,700-report archive-order prefix has a median of 7 static tokens/report and zero explicit weak ATT&CK/MBC labels; it still lacks the PE structure needed for a complete static/dynamic hybrid benchmark. Family labels alone do not supervise behavior.

Event truncation previously returned after the first process reached the cap, before global sorting. It now selects globally earliest calls using a bounded heap, then compresses repeats. Numeric and ISO/date-time timestamps retain elapsed-time information. The parser was validated on 1,700 real WinMET reports (2,494,447 normalized events, zero invalid reports), but this does not verify every CAPE schema variant or independently annotated behavior. The first 32-report diagnostic subset produced 36 autorun-related events and eight suspected T1547.001 chains; none had the full same-key successful open/write evidence needed for `confirmed`. Across the 1,700 prefix, the 15-rule engine found suspected/confirmed event chains for 12 techniques; T1547.001 remained 493 suspected and zero confirmed. These are rule-derived weak labels, not expert ground truth. Training confirmed only 45 strong behavior-positive observations and no valid behavior negatives, so the behavior head was disabled. A 500-report family-attention pilot trained and ran a held-out test, but its 34 labeled test rows are far too small and biased for acceptance. No behavior accuracy claim is inferred. See [the bounded workflow](winmet-workflow.md).

WinMET provides 31,844 CAPE traces across five volumes with process/API/resource sequence detail and reports roughly 13 GB compressed / 750 GB uncompressed. License/source metadata and checksums for volume 1 and the consensus label file are recorded in `configs/winmet.lock.json`.
